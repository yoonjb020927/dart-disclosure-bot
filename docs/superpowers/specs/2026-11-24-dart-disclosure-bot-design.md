# DART 공시 요약·분류봇 설계

작성일: 2026-11-24

## 1. 의도와 이유

- 매일 전날 DART 공시를 자동으로 수집해서 LLM(Gemini)이 요약하고, **유형**과 **영향(긍정/부정/중립)**으로 분류한다.
- 공시 후 실제 주가 반응을 백테스트해서 **"LLM 분류가 실제로 맞았는가"**를 숫자로 검증한다.
- 목적: 취업용 포트폴리오. 금융 데이터 처리와 AI 활용 역량을 보여주는 것이 목표다.
  - 보는 사람(면접관, 채용 담당자)이 확인할 것은 세 가지다.
    1. 실제로 매일 돌아갔다는 증거
    2. 검증 결과의 숫자, 그리고 그 숫자의 한계를 이해하고 있다는 것
    3. 링크 하나로 바로 이해되는 결과 화면
- 기존 `krx-daily-report` 프로젝트와는 **별도 저장소**로 만든다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 평일과 주말 모두 매일 자동으로 실행되고, 사람이 개입하지 않아도 데이터가 쌓인다.
- 공시마다 3줄 요약, 유형, 영향, 확신도, 판단 근거 한 줄을 남긴다.
- 유형별·영향별 공시 후 초과수익률과 LLM 분류 적중률을 대시보드에서 보여준다.
- README만 읽어도 문제 정의, 구조, 결과, 한계를 파악할 수 있다.

**비목표**
- 실시간 알림, 장중 대응
- 매매 신호나 자동매매
- 투자 조언
- 모바일 앱, 로그인 기능

**반목표** (기술적으로는 돌아가도 이렇게 되면 실패로 본다)
- 미래 정보가 섞인 백테스트로 적중률을 부풀리는 것. 4.6절 참고.
- 비용이 발생하는 것. 전 구성 무료여야 한다.
- API 키가 저장소에 노출되는 것.
- 표본이 몇 건뿐인 결과를 그럴듯하게 포장하는 것. 표본 수와 유의성을 항상 같이 표시한다.

## 3. 제약

- 비용 0원: GitHub Actions(공개 저장소), GitHub Pages, Gemini API 무료 구간, OpenDART(무료, 일 20,000회 한도)
- Gemini 무료 구간의 분당·일일 호출 한도 안에서 동작해야 한다. 한도 수치는 변할 수 있으므로 설정값으로 둔다.
- 개발 환경: Windows PC, Python. 실행 환경: GitHub Actions(ubuntu)
- 사용자는 대학생이다. 설정 단계가 적어야 하고, README에 키 발급부터 따라 할 수 있는 안내가 있어야 한다.

## 4. 구조 (사용자가 정한 것 + 설계 결정)

### 4.1 접근 방식 비교 (사용자 선택: A)

| | 구성 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | GitHub Actions + 저장소에 데이터 파일 + GitHub Pages 정적 대시보드 | 전부 무료, PC가 꺼져 있어도 실행, 실행 기록이 운영 증거로 남음, 링크로 공유 | 대시보드 인터랙션이 제한적 |
| B | 로컬 작업 스케줄러 + 로컬 DB + Streamlit | 대시보드 자유도 높고 쉬움 | PC가 꺼지면 누락, 공유 어려움 |
| C | Supabase + Streamlit Cloud + Actions | 실무에 가장 가깝고 인터랙티브 | 설정 복잡, 무료 플랜 제약 |

A를 고른 이유: 포트폴리오의 핵심 요구("매일 돌았다"는 증거, 링크 공유)를 가장 단순하게 충족한다. 나중에 쌓인 데이터를 C로 옮길 수 있다.

### 4.2 실행 흐름 (하루 1회, KST 07:00, 하나의 워크플로)

1. **수집**: OpenDART `list.json`으로 마지막 처리일 다음 날부터 어제까지의 공시를 페이지 단위로 모두 받는다. 마지막 처리일은 상태 파일에 저장하므로, 실행이 빠진 날이 있어도 다음 실행에서 따라잡는다.
2. **필터**: 유가증권(Y)과 코스닥(K) 상장사만 남긴다. 그다음 제목 키워드 규칙으로 대상 유형 후보만 남긴다.
   - 정정공시(`[기재정정]` 등)는 표시만 하고 백테스트에서는 제외한다. 원공시만 이벤트로 본다.
3. **본문 확보**: `document.xml`에서 원문을 받아 텍스트를 추출하고 일정 길이로 자른다. 실패하면 제목만으로 분류하고 그 사실을 기록한다.
4. **LLM 분류**: Gemini 구조화 출력(JSON 스키마)을 사용한다.
   - 출력 필드: `summary`(한국어 3줄), `type`(아래 enum), `sentiment`(긍정/부정/중립), `confidence`(0~1), `rationale`(한 줄)
   - 모델 이름은 설정값으로 둔다(기본: Flash 계열 무료 모델). 프롬프트에도 버전을 붙여 결과에 같이 기록한다. 나중에 다른 LLM과 비교할 수 있게 LLM 호출부는 교체 가능한 인터페이스로 만든다.
   - 호출 한도를 넘지 않도록 속도를 조절하고 하루 처리 상한을 둔다. 다 못 처리한 건은 대기열에 남겨 다음 실행에서 이어서 처리한다. 우선순위는 최신 공시부터이고, 소급분은 그다음이다.
   - **LLM에 넣는 대상은 2단계 키워드 필터를 통과한 후보만이다** (설계자 결정). 키워드에 안 걸린 공시는 분류하지 않고 건수만 운영 현황에 기록한다. `기타`는 후보 중 LLM이 어느 유형에도 해당하지 않는다고 판단한 경우이고, 백테스트 집계에서 제외한다. 키워드 누락은 주기적으로 제외된 제목 목록을 보고 보완한다.
5. **주가 수집과 백테스트**: 4.5절 참고. 매 실행마다 다시 계산한다(비용이 거의 없음).
6. **대시보드 생성**: 정적 HTML과 JSON을 만들어 Pages로 배포한다.
7. **커밋**: 새 데이터와 결과를 저장소에 커밋한다. 이 커밋 기록이 운영 증거가 된다.

**재실행 안전성**: 접수번호(`rcept_no`)로 중복을 제거하므로, 같은 날을 다시 돌려도 결과가 두 번 쌓이지 않는다.

### 4.3 공시 유형 (enum)

유상증자 / 무상증자 / 자기주식 취득 / 자기주식 처분 / 자기주식 소각 / 단일판매·공급계약(수주) / 최대주주 변경 / 전환사채·신주인수권부사채 발행 / 합병·분할 / 영업(잠정)실적 / 기타

### 4.4 데이터 저장

- 공시와 분류 결과: 월별 JSONL 파일. 사람이 읽을 수 있고, git 변경 내역도 보기 좋다.
- 주가: 종목별 캐시 파일
- 백테스트 결과: 집계 JSON. 대시보드가 이 파일을 그대로 읽는다.
- 상태: 마지막 처리일, 미처리 대기열

### 4.5 백테스트 방법

- **이벤트일 t0**: 공시 접수일(`rcept_dt`). 장중 공시와 장 마감 후 공시를 모두 포함하기 위해, 기준가는 t0 전 거래일 종가로 한다. 접수일이 휴장일이면 다음 거래일을 t0으로 한다.
- **지표**: 시장조정 누적초과수익률 CAR. 종목 수익률에서 해당 시장지수(코스피 또는 코스닥) 수익률을 뺀 값이다.
  - 기간: [0,+1], [0,+5], [0,+20] 거래일
  - 해당 기간이 아직 지나지 않은 공시는 "대기 중"으로 표시하고 집계에서 제외한다.
- **적중 판정** (주 기준: CAR[0,+1], 임계값 기본 ±1%, 설정 가능)
  - 긍정: CAR > +임계값
  - 부정: CAR < −임계값
  - 중립: |CAR| ≤ 임계값
- **보고 항목**
  - 유형별·영향별 평균 CAR과 표본 수, t검정 p값
  - 혼동행렬
  - 방향 적중률(중립 제외)
  - 확신도 구간별 적중률
  - 임계값 민감도(0.5%, 1%, 2%)
  - 표본이 30건 미만인 그룹은 "표본 부족"으로 표시한다.

### 4.6 미래 정보 혼입 방지 (반목표 대응)

- **과거 1년 소급 분류 (사용자 결정: 첫 결과물)**: 최근 1년(2025-11-24 ~ 2026-11-23) 치 공시를 먼저 수집·분류·백테스트해서 첫 결과를 낸다. 무료 한도 때문에 여러 날에 나눠 처리한다.
  - 호출 수를 줄이기 위해 한 번 호출할 때 공시 여러 건을 묶어서 분류한다(설계자 결정).
  - 소요 일수는 실제 후보 건수와 무료 한도를 측정한 뒤 README에 기록한다.
  - LLM이 학습 과정에서 그 시기의 뉴스, 즉 결과를 이미 알고 있을 수 있다. 그래서 소급분은 `backfill`로 표시한다.
  - **혼입 완화 (설계자 결정)**: 프롬프트에 넣을 때 회사명, 종목코드, 날짜를 가리고(예: "A사", "T일") 본문 내용만으로 판단하게 한다. live에도 똑같이 적용해서 두 집단이 같은 분류기를 쓰게 한다. 회사명은 화면에 표시할 때만 다시 붙인다.
- **실시간 운영분**: 운영 시작 후 매일 분류한 공시는 `live`로 표시한다. 분류 시점에는 주가 반응이 존재하지 않았으므로 이 결과만 "깨끗한 검증"이다.
- 대시보드와 README에서 두 집단을 **분리해서** 보여주고, 그 이유를 설명한다.

### 4.7 대시보드 (GitHub Pages, 정적)

1. **오늘의 공시**: 회사명, 제목(DART 원문 링크), 유형, 영향 배지, 3줄 요약, 확신도. 날짜 선택과 간단한 유형 필터를 제공한다.
2. **검증 결과**: 영향별 평균 CAR 막대그래프(기간별), 유형별 표, 혼동행렬, live/backfill 전환
3. **운영 현황**: 마지막 실행 시각, 누적 처리 건수, 일별 처리량, 실패 건수

### 4.8 보안과 운영

- `DART_API_KEY`, `GEMINI_API_KEY`는 GitHub Secrets에만 둔다. 로컬에서는 `.env`를 쓰고 `.gitignore`에 포함한다.
- 실패하면 워크플로가 실패로 끝나게 해서 GitHub이 메일로 알려주도록 한다. 일부만 실패하면 성공한 결과는 저장하고 실패 건은 기록한다.
- 공개 저장소 Actions는 60일간 저장소 활동이 없으면 예약 실행이 멈춘다. 매일 데이터 커밋이 생기므로 해당하지 않지만, README에 적어둔다.

### 4.9 품질

- pytest 단위 테스트: 필터 규칙, 파싱, CAR 계산, 적중 판정, 중복 제거. LLM과 외부 API는 목(mock)으로 대체한다.
- 커버리지 목표 80%
- 저장소에 PR이 올라오면 테스트가 자동으로 돌게 한다.

### 4.10 README (포트폴리오 문서)

문제 정의 → 구조도 → 핵심 결과(대시보드 링크, 주요 수치) → 검증 방법 → 한계(표본, 시장조정 모델의 단순함, 소급분 혼입, 무료 모델 품질) → 실행 방법(키 발급부터) → 향후 계획

### 4.11 krx-daily-report에서 가져올 것 (사용자 허락)

코드를 그대로 의존하지 않고, 검증된 패턴을 새 저장소에 옮겨 쓴다.
- KRX 클라이언트: 재시도, 401/403 구분, 휴장일 판정
- 워크플로 패턴
  - 데이터 커밋 전에 `git pull --rebase`
  - 실패하면 Issue 자동 생성
  - `workflow_dispatch` 수동 실행용 backfill 워크플로
  - `concurrency`로 동시 실행 방지
- CI: `pytest --cov-fail-under=80`
- 시크릿: `KRX_API_KEY`(기존과 같은 키를 새 저장소 Secrets에 등록), `DART_API_KEY`, `GEMINI_API_KEY`

### 4.12 만드는 순서 (첫 결과물 = 최근 1년 결과)

1. 수집 기반: DART 공시 목록, KRX 주가·지수, 1년 치 원자료 저장
2. 분류: Gemini 분류기, 대기열, 소급 분류 워크플로. 이 워크플로를 매일 돌려 1년 치를 소화한다.
3. 백테스트: CAR 계산, 적중 판정, 집계
4. 대시보드와 README에 1년 결과를 공개한다. **여기까지가 첫 결과물이다.**
5. 매일 운영 워크플로를 켜고 live 데이터 축적을 시작한다.
   - 2단계가 끝나는 대로 일찍 켜도 된다. live 표본이 하루라도 빨리 쌓이기 때문이다.

## 6. 확인이 필요한 위험

- **주가 데이터 출처 (설계자 결정)**: **KRX Open API**(`data-dbg.krx.co.kr`)를 쓴다. 사용자의 `krx-daily-report`가 같은 API를 GitHub Actions에서 매일 문제없이 호출하고 있어서, 해외 IP 차단 걱정이 없다는 것이 이미 확인됐다.
  - 하루 한 번 호출하면 시장 전체 종목의 일별 시세가 온다. 그래서 1년 소급도 약 250일 × (유가증권, 코스닥, 지수 2종) 호출로 끝난다.
  - 필요한 서비스: 유가증권·코스닥 일별매매정보, KOSPI·KOSDAQ 지수 일별시세. KRX Open API에서 **서비스별 이용 신청이 따로 필요하다.** 기존 키로 ETF·파생 서비스만 승인돼 있다면 추가 신청이 필요하다. 엔드포인트 이름과 필드는 구현 초기에 실제 응답으로 확인한다.
  - KRX Open API가 안 되면 yfinance(`.KS`/`.KQ`, 지수 `^KS11`/`^KQ11`)로 대체한다. 로컬 수집이나 자체 러너는 쓰지 않는다. 출처는 결과에 기록한다.
- **모델·프롬프트 버전 변경**: 결과는 분류기 버전(모델 + 프롬프트)별로 따로 집계한다. 대시보드 기본 화면은 현재 버전을 보여주고, 이전 버전은 선택해서 볼 수 있다(설계자 결정). 버전 변경을 줄이기 위해 별칭이 아닌 고정 모델 이름을 쓴다.
- **Gemini 무료 구간의 실제 한도**: 하루 대상 공시 수와 비교해서 하루 처리 상한을 정한다.
